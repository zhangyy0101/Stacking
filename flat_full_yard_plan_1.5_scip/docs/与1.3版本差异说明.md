# 与 1.3 版本差异说明

本文档对比 `flat_full_yard_plan_1.4_scip` 与 `flat_full_yard_plan_1.3_scip`。
下文统一使用“1.4”和“1.3”代指两个版本。

## 1. 目录结构调整

1.3 的大部分实现文件都直接放在根目录，例如 `input_adapter_standard.py`、`column_generation_planner.py`、`planning_large_solver.py` 等。1.4 按职责拆分为多层目录，根目录只保留 4 个运行入口：

- `run_flat_full_yard_plan.py`：全流程入口
- `run_large_plan.py`：单独大计划入口
- `run_medium_small_column_generation.py`：单独中小计划入口
- `run_small_plan_from_medium.py`：单独小计划入口

实现代码移动到以下目录：

- `adapters/`：输入适配、DataFrame 与 JSON 输入转换、大计划/中小计划输入构造
- `api/`：面向 DataFrame 调用的 API
- `large_plan/`：大计划求解器和大计划可视化
- `medium_small/`：中小计划列生成、桥接逻辑、单独小计划逻辑
- `block_bay_planning/`：中小计划数据模型、数据加载、需求计算等基础模块
- `data_examples/`：示例输入数据
- `docs/`：说明文档
- `assets/`：图片资源

1.4 默认输入文件从根目录的 `input_data.json` 移到 `data_examples/input_data.json`。`adjust_plan_info.json` 也移到 `data_examples/`，作为调整规则格式参考；实际运行默认读取的是 `input_data.json` 里的 `adjust_plan_info` 字段。

## 2. 运行入口保持但导入路径更新

1.4 仍通过根目录 4 个 `run_*.py` 文件运行，运行方式基本不变。内部导入路径改为分层包路径：

- `adapters.input_adapter_gd`
- `adapters.input_adapter_standard`
- `api.planning_api`
- `large_plan.solver`
- `large_plan.visualize`
- `medium_small.bridge`
- `medium_small.column_generation_planner`
- `medium_small.small_plan_from_medium`

因此，如果外部代码曾直接导入根目录模块名，例如：

```python
from input_adapter_gd import InputAdapterGd
from planning_api import solve_full_yard_plan_df
from column_generation_planner import ColumnGenerationPlanner
```

需要改为：

```python
from adapters.input_adapter_gd import InputAdapterGd
from api.planning_api import solve_full_yard_plan_df
from medium_small.column_generation_planner import ColumnGenerationPlanner
```

命令行入口仍推荐使用根目录 `run_*.py`。

## 3. 输入输出对接增强

1.4 新增并完善了面向标准输入对象和 DataFrame 的调用能力：

- 增加 `api/planning_api.py`，提供：
  - `solve_large_plan_df`
  - `solve_medium_small_plan_df`
  - `solve_small_plan_df`
  - `solve_full_yard_plan_df`
  - `YardPlanAlgorithmConfig`
- `adapters/input_adapter_gd.py` 支持保存和恢复完整 `InputAdapterGd` JSON，包括 DataFrame 字段和算法参数字段。
- `adapters/input_adapter_standard.py` 承担大计划和中小计划的统一输入构造，避免本地运行必须先落地成大量中间 CSV。

1.4 仍保留本地脚本输出 CSV/JSON 的能力，同时支持用 DataFrame 在内存中串联大计划、中小计划和小计划。

## 4. 大计划相关变化

1.4 大计划仍使用原求解器逻辑，但输入输出适配层有明显增强：

- 支持从 `InputAdapterGd` 直接构造大计划输入。
- 输出 `allocation.csv` 时保留 `new_qty` 字段，用于表示扣除已在场箱后的新增计划量。
- 中小计划读取大计划时优先按 `new_qty` 作为计划箱量，避免把已在场箱再次纳入中小计划。
- 支持 `adjust_plan_info` 中大计划层面的指定箱区、禁止箱区、增加箱区、减少箱区约束。
- 可视化模块移动到 `large_plan/visualize.py`，图片资源移动到 `assets/`。

注意：当前环境如果没有安装 `Pillow`，大计划可视化会跳过，但大计划求解和 CSV 输出不受影响。

## 5. 中小计划输入规则变化

1.3 的中小计划属性规则更偏向全局规则。1.4 支持每个航次独立配置：

- `rough_attr`：粗属性组分组依据
- `detail_attr`：细属性组分组依据
- `bay_rules`：禁止同贝位混放的属性
- `row_rules`：禁止同排混放的属性
- `weight_level`：重量分组节点

这些字段在 1.4 中按航次组织为字典，key 是航次 id，value 是该航次对应规则。例如重量等级 `[0, 10, 15, 20, 25, 30]` 表示 `0-10`、`10-15`、`15-20`、`20-25`、`25-30`、`>30`。

相关变化分布在：

- `adapters/input_adapter_gd.py`
- `adapters/input_adapter_standard.py`
- `block_bay_planning/models.py`
- `block_bay_planning/data_loader.py`
- `medium_small/column_generation_planner.py`

## 6. 中小计划 bay-level add/remove 约束

1.4 支持中小计划和单独小计划的细粒度贝位 add/remove 约束：

- `add` 中的贝位表示必须使用。
- `remove` 中的贝位表示禁止使用。

这些约束会进入中小计划模型，而不仅是输入层过滤：

- 候选贝位生成时过滤禁止贝位。
- 候选数量截断时保留必须使用贝位。
- 主问题中加入必须使用贝位的硬约束。
- 修复和 LNS 阶段也检查禁止贝位、必须贝位。
- 诊断信息中输出未满足必须贝位、误用禁止贝位等信息。

涉及字段包括：

- `user_group_bay_requirements`
- `user_group_bay_blocklist`
- `user_bay_adjust_rules`
- `user_bay_constraint_summary`

## 7. 中小计划算法变化

1.4 的中小计划列生成器相比 1.3 有较大增强：

- 支持按航次读取 `bay_no_mix`、`row_no_mix`、重量等级。
- 支持 `medium_plan_bay_quota`，使单独小计划可按外部中计划的 bay-level 中计划约束运行。
- 修正中计划和小计划箱量口径，避免把已在场箱重复规划。
- 单独小计划读取外部中计划时，不再优先假设外部中计划区分 `document_boxes` 和 `forecast_fallback_boxes`。
- 诊断信息增加：
  - `planned_medium_boxes`
  - `planned_small_boxes`
  - `unplaced_boxes`
  - `document_boxes`
  - `forecast_fallback_boxes`
  - bay-level 约束违反详情

1.4 中小计划核心文件移动为 `medium_small/column_generation_planner.py`。

## 8. 单独运行能力

1.4 明确支持以下四种运行方式：

1. 全流程：`run_flat_full_yard_plan.py`
2. 单独大计划：`run_large_plan.py`
3. 单独中小计划：`run_medium_small_column_generation.py`
4. 单独小计划：`run_small_plan_from_medium.py`

各入口默认使用：

```text
flat_full_yard_plan_1.4_scip/data_examples/input_data.json
```

单独中小计划需要传入大计划 CSV；单独小计划需要传入外部中计划 CSV，可选传入大计划 CSV。

## 9. 验证结果

整理后已使用完整数据运行验证：

| 运行方式 | 结果 | 未放置/未满足 | 运行时间 |
|---|---:|---:|---:|
| 全流程 | 成功 | `unplaced_boxes=0` | 约 `5m46s`，其中中小计划约 `2m38s` |
| 单独大计划 | 成功，求解器状态 `TIMELIMIT` 但有可行解 | `unmet20_total=0`, `unmet40_total=0` | 约 `2m31s`，求解器时间 `120s` |
| 单独中小计划 | 成功 | `unplaced_boxes=0` | 约 `3m04s`，诊断耗时 `2m36s` |
| 单独小计划 | 成功 | `unplaced_boxes=0` | 约 `1m07s`，诊断耗时 `38s` |

说明：`TIMELIMIT` 是大计划在给定时间限制内停止，但已经找到满足箱量需求的可行解；关键未满足量为 0。

## 10. 迁移注意事项

- 直接运行脚本时，仍使用根目录 `run_*.py`。
- 外部 Python 代码若导入内部模块，需要改成新的包路径。
- `input_data.json` 已移动到 `data_examples/`。
- `adjust_plan_info.json` 不是默认运行文件，只是格式参考；真实生效数据应写入 `input_data.json` 的 `adjust_plan_info` 字段，或由外部构造 `InputAdapterGd.adjust_plan_info`。
- 如果需要大计划图片可视化，请在运行环境安装 `Pillow`。
