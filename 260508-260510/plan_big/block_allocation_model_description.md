# 事件驱动滚动箱区分配模型说明

本文档用于向 Codex 说明当前 Python/Gurobi 代码中的数学模型、参数含义、决策变量、约束条件、目标函数，以及第一次规划与后续规划之间的区别。

当前模型只描述**单个规划时刻 \(\theta\)** 下的 Gurobi 求解问题。时间滚动、数据读取、容量更新、历史状态更新等逻辑由外部程序完成。

---

## 1. 模型任务

模型用于解决出口箱箱区层级规划问题。在某个规划时刻 \(\theta\)，给定当前需要新增规划的航次、各航次 20 尺和 40 尺箱需求、箱区剩余容量、航次到箱区距离、不可用箱区、历史已选箱区等信息，模型需要决定：

1. 每个航次的 20 尺箱分配到哪些箱区；
2. 每个航次的 40 尺箱分配到哪些箱区；
3. 当前规划完成后，每个航次总体占用了哪些箱区；
4. 后续规划时是否启用了新的箱区；
5. 同日开港航次是否共用箱区；
6. 某个箱区是否服务了超过 2 个活跃航次；
7. 各航次到泊位的累计平均距离是否过大。

模型不考虑卸货港、箱高、危险品、超限、重量等级等箱属性组。模型只区分 20 尺和 40 尺箱，因为这涉及物理容量约束。

---

## 2. 时间机制

模型采用**事件驱动滚动规划**。

模型本身不建立时间维度变量，例如不使用：

\[
x_{v,a,t}
\]

而是每到一个规划事件 \(\theta\)，由外部程序更新参数，然后调用一次 Gurobi 求解模型。

时间主要通过以下参数进入模型：

- 当前新增规划需求：\(R_v^{20}(\theta), R_v^{40}(\theta)\)；
- 当前箱区剩余容量：\(C_a^{20}(\theta), C_a^{40}(\theta)\)；
- 当前不可用箱区参数：\(B_{v,a}(\theta)\)；
- 当前时刻之前历史已选箱区：\(H_{v,a}(\theta^-)\)；
- 当前时刻之前已规划箱量：\(P_v^{20}(\theta^-), P_v^{40}(\theta^-)\)；
- 当前时刻之前累计距离成本：\(G_v(\theta^-)\)。

---

## 3. 航次规划事件

设航次 \(v\) 的开港时间为：

\[
T_v^{open}
\]

每个航次生成三个规划事件：

\[
\theta_{v,0}=T_v^{open}-24h
\]

\[
\theta_{v,1}=T_v^{open}+24h
\]

\[
\theta_{v,2}=T_v^{open}+48h
\]

对应累计规划比例为：

\[
\rho_v(\theta)=
\begin{cases}
0.7, & \theta=\theta_{v,0} \\
0.9, & \theta=\theta_{v,1} \\
1.0, & \theta=\theta_{v,2}
\end{cases}
\]

解释如下：

| 规划事件 | 时间 | 累计规划比例 | 当前新增比例 |
|---|---:|---:|---:|
| 第一次规划 | 开港前 24 小时 | 70% | 新增 70% |
| 第二次规划 | 开港后 24 小时 | 90% | 新增 20% |
| 第三次规划 | 开港后 48 小时 | 100% | 新增 10% |

注意：

- 开港当天本身不一定新增规划；
- 开港前一天和开港当天都是累计规划 70%；
- 如果当前系统时间已经晚于某些航次的规划事件，但这些航次尚未规划，则外部程序应在当前时刻补做规划；
- 当前 Gurobi 模型只处理某一个规划时刻 \(\theta\)，不负责生成规划事件。

---

## 4. 第一次规划与后续规划的区别

### 4.1 第一次规划

第一次规划发生在：

\[
\theta = T_v^{open}-24h
\]

第一次规划要完成：

1. 分配该航次约 70% 的箱量；
2. 为该航次确定主箱区集合；
3. 控制该航次使用箱区数量；
4. 为后续 20% 和 10% 补充规划提供历史箱区集合。

第一次规划时，加入箱区数量约束：

\[
K_v^{min} \leq \sum_{a\in\mathcal A} w_{v,a} \leq K_v^{max}
\]

其中：

- \(w_{v,a}=1\)：当前规划完成后，航次 \(v\) 的整体计划使用箱区 \(a\)；
- \(K_v^{min}\)：航次 \(v\) 推荐箱区数量下界；
- \(K_v^{max}\)：航次 \(v\) 推荐箱区数量上界。

第一次规划中，变量 \(n_{v,a}\) 固定为 0。原因是第一次规划本身就是在建立主箱区集合，不应被视为“新开箱区”。

### 4.2 后续规划

后续规划包括：

- 第二次规划：开港后 24 小时，累计规划到 90%；
- 第三次规划：开港后 48 小时，累计规划到 100%。

后续规划的目标是：

1. 补充分配剩余 20% 或 10% 的箱量；
2. 尽量把新增箱子放回第一次规划时已经选择的箱区；
3. 如果原箱区容量不足、不可用或冲突，才允许启用新箱区；
4. 启用新箱区时，通过 \(n_{v,a}\) 记录，并在目标函数中强惩罚。

后续规划中新开箱区识别逻辑为：

\[
n_{v,a} \geq w_{v,a} - H_{v,a}(\theta^-)
\]

\[
n_{v,a} \leq w_{v,a}
\]

\[
n_{v,a} \leq 1 - H_{v,a}(\theta^-)
\]

如果历史上没用过箱区 \(a\)，即 \(H_{v,a}(\theta^-)=0\)，但当前规划完成后使用了该箱区，即 \(w_{v,a}=1\)，那么 \(n_{v,a}=1\)。

## 5. 集合定义

### 5.1 当前新增规划航次集合

\[
\mathcal V^+(\theta)
\]

表示当前规划时刻 \(\theta\) 需要新增规划箱量的航次集合。

代码中对应：

```python
V_plus: List[Vessel]
```

### 5.2 活跃航次集合

\[
\mathcal V^{act}(\theta)
\]

表示当前规划时刻仍然占用堆场规划资源的航次集合。

该集合包括：

- 当前新增规划的航次；
- 之前已经规划过但仍然占用箱区资源的航次；
- 后续仍可能继续补充规划的航次。

代码中对应：

```python
V_act: List[Vessel]
```

### 5.3 候选箱区集合

\[
\mathcal A
\]

表示候选箱区集合，通常由以下预处理得到：

\[
\mathcal A = \text{OF适放箱区} - \text{关闭箱区}
\]

代码中对应：

```python
A: List[Area]
```

### 5.4 同日开港航次对集合

\[
\mathcal P^{same}(\theta)
\]

表示同一天开港的航次对集合。如果航次 \(u\) 和航次 \(v\) 同日开港，则：

\[
(u,v) \in \mathcal P^{same}(\theta)
\]

代码中对应：

```python
P_same: List[Tuple[Vessel, Vessel]]
```

## 6. 参数定义

### 6.1 当前新增规划需求

20 尺箱新增规划需求：

\[
R_v^{20}(\theta)
\]

40 尺箱新增规划需求：

\[
R_v^{40}(\theta)
\]

计算方式为：

\[
R_v^{20}(\theta)
=
\max
\left\{
0,
\left\lceil \rho_v(\theta)D_v^{20}\right\rceil
-
P_v^{20}(\theta^-)
\right\}
\]

\[
R_v^{40}(\theta)
=
\max
\left\{
0,
\left\lceil \rho_v(\theta)D_v^{40}\right\rceil
-
P_v^{40}(\theta^-)
\right\}
\]

代码中对应：

```python
R20: Dict[Vessel, int]
R40: Dict[Vessel, int]
```

### 6.2 箱区剩余容量

20 尺等价剩余容量：

\[
C_a^{20}(\theta)
\]

40 尺剩余容量：

\[
C_a^{40}(\theta)
\]

代码中对应：

```python
C20: Dict[Area, int]
C40: Dict[Area, int]
```

注意：

- \(C_a^{20}\) 表示 20 尺等价容量；
- 一个 40 尺箱消耗 2 个 20 尺等价容量；
- \(C_a^{40}\) 表示真实可放 40 尺箱的能力；
- 不可将 \(C_a^{20}\) 和 \(C_a^{40}\) 简单相加，因为二者可能对应重叠空间。

### 6.3 距离参数

\[
d_{v,a}
\]

表示航次 \(v\) 的靠泊泊位到箱区 \(a\) 的距离。

代码中对应：

```python
distance: Dict[Tuple[Vessel, Area], float]
```

### 6.4 箱区不可用参数

\[
B_{v,a}(\theta)=
\begin{cases}
1, & \text{箱区 }a\text{ 对航次 }v\text{ 当前不可用} \\
0, & \text{箱区 }a\text{ 对航次 }v\text{ 当前可用}
\end{cases}
\]

代码中对应：

```python
B: Dict[Tuple[Vessel, Area], int]
```

不可用原因包括：

1. 箱区关闭；
2. 箱区不属于 OF 适放箱区；
3. 箱区当前容量不足；
4. 箱区在航次开港当天处于装船任务时段；
5. 箱区被其他 TOPS 生效计划占用；
6. 其他生产规则禁止使用。

### 6.5 历史已选箱区参数

\[
H_{v,a}(\theta^-)=
\begin{cases}
1, & \text{航次 }v\text{ 历史上已经使用过箱区 }a \\
0, & \text{否则}
\end{cases}
\]

代码中对应：

```python
H: Dict[Tuple[Vessel, Area], int]
```

该参数用于后续规划时尽量沿用第一次规划的主箱区。

### 6.6 历史已规划箱量

\[
P_v^{20}(\theta^-),\quad P_v^{40}(\theta^-)
\]

代码中对应：

```python
P20_prev: Dict[Vessel, int]
P40_prev: Dict[Vessel, int]
```

### 6.7 历史累计距离成本

\[
G_v(\theta^-)
\]

表示当前时刻之前，航次 \(v\) 已规划箱量的累计距离成本。

代码中对应：

```python
G_prev: Dict[Vessel, float]
```

求解后更新方式为：

\[
G_v(\theta)=G_v(\theta^-)+\sum_{a\in\mathcal A}d_{v,a}(x_{v,a}^{20}+x_{v,a}^{40})
\]

### 6.8 第一次规划箱区数量上下界

\[
K_v^{min},\quad K_v^{max}
\]

表示第一次规划时，航次 \(v\) 的推荐箱区数量上下界。

代码中对应：

```python
K_min: Dict[Vessel, int]
K_max: Dict[Vessel, int]
```

该参数只对第一次规划航次生效。

### 6.9 权重参数

代码中对应：

```python
lambda_dist
lambda_fair
lambda_frag
lambda_same
lambda_over
M_new
M_miss
```

含义如下：

| 参数 | 含义 |
|---|---|
| `lambda_dist` | 总距离成本权重 |
| `lambda_fair` | 最大累计平均距离公平项权重 |
| `lambda_frag` | 当前新增规划碎片化惩罚权重 |
| `lambda_same` | 同日开港航次共用箱区惩罚权重 |
| `lambda_over` | 一个箱区服务超过 2 个航次的惩罚权重 |
| `M_new` | 后续规划中新开箱区惩罚权重 |
| `M_miss` | 未满足需求惩罚权重 |

建议权重优先级：

\[
M^{miss} \gg M^{new} \gg \lambda_{same},\lambda_{over} \gg \lambda_{dist},\lambda_{fair},\lambda_{frag}
\]

## 7. 决策变量

### 7.1 20 尺箱分配变量

\[
x_{v,a}^{20}\in\mathbb Z_+
\]

表示当前规划时刻 \(\theta\)，航次 \(v\) 新增分配到箱区 \(a\) 的 20 尺箱数量。

代码中对应：

```python
x20[v, a]
```

### 7.2 40 尺箱分配变量

\[
x_{v,a}^{40}\in\mathbb Z_+
\]

表示当前规划时刻 \(\theta\)，航次 \(v\) 新增分配到箱区 \(a\) 的 40 尺箱数量。

代码中对应：

```python
x40[v, a]
```

### 7.3 当前使用箱区变量

\[
z_{v,a}\in\{0,1\}
\]

表示当前这一次规划中，航次 \(v\) 是否往箱区 \(a\) 分配了新增箱量。

代码中对应：

```python
z[v, a]
```

### 7.4 总体使用箱区变量

\[
w_{v,a}\in\{0,1\}
\]

表示当前规划完成后，航次 \(v\) 的整体规划中是否使用箱区 \(a\)。

代码中对应：

```python
w[v, a]
```

注意：

- \(z_{v,a}\)：当前这一次规划是否使用箱区；
- \(w_{v,a}\)：截至当前，航次整体规划是否包含该箱区。

### 7.5 新开箱区变量

\[
n_{v,a}\in\{0,1\}
\]

表示当前规划是否为航次 \(v\) 新启用了箱区 \(a\)。

代码中对应：

```python
n[v, a]
```

第一次规划中，\(n_{v,a}\) 固定为 0。后续规划中，若启用历史中没有用过的箱区，则 \(n_{v,a}=1\)。

### 7.6 同日开港共用箱区变量

\[
q_{u,v,a}\in\{0,1\}
\]

表示同日开港航次 \(u\) 和 \(v\) 是否共用箱区 \(a\)。

代码中对应：

```python
q[u, v, a]
```

### 7.7 箱区服务航次数超额变量

\[
h_a\geq 0
\]

表示箱区 \(a\) 服务超过 2 个航次的超额数量。

代码中对应：

```python
h[a]
```

### 7.8 最大累计平均距离变量

\[
\eta\geq 0
\]

表示当前所有活跃航次中的最大累计平均距离。

代码中对应：

```python
eta
```

### 7.9 未满足需求变量

\[
s_v^{20}\geq 0,\quad s_v^{40}\geq 0
\]

表示当前未满足的 20 尺和 40 尺新增规划需求。

代码中对应：

```python
s20[v]
s40[v]
```

调试阶段建议允许该变量存在，并在目标函数中施加极大惩罚。模型稳定后可以将其固定为 0。

## 8. 约束条件

### 8.1 20 尺箱需求满足约束

\[
\sum_{a\in\mathcal A}x_{v,a}^{20}+s_v^{20}=R_v^{20}(\theta),\quad \forall v\in\mathcal V^+(\theta)
\]

代码对应：

```python
sum(x20[v, a] for a in A) + s20[v] == R20[v]
```

含义：当前应规划的 20 尺箱，要么分配到箱区，要么记为未满足需求。

### 8.2 40 尺箱需求满足约束

\[
\sum_{a\in\mathcal A}x_{v,a}^{40}+s_v^{40}=R_v^{40}(\theta),\quad \forall v\in\mathcal V^+(\theta)
\]

代码对应：

```python
sum(x40[v, a] for a in A) + s40[v] == R40[v]
```

### 8.3 40 尺箱容量约束

\[
\sum_{v\in\mathcal V^+(\theta)}x_{v,a}^{40}\leq C_a^{40}(\theta),\quad \forall a\in\mathcal A
\]

代码对应：

```python
sum(x40[v, a] for v in V_plus) <= C40[a]
```

含义：箱区 \(a\) 的 40 尺箱分配量不能超过其 40 尺容量。

### 8.4 20 尺等价容量约束

\[
\sum_{v\in\mathcal V^+(\theta)}x_{v,a}^{20}+2\sum_{v\in\mathcal V^+(\theta)}x_{v,a}^{40}\leq C_a^{20}(\theta),\quad \forall a\in\mathcal A
\]

代码对应：

```python
sum(x20[v, a] for v in V_plus) + 2 * sum(x40[v, a] for v in V_plus) <= C20[a]
```

含义：40 尺箱占用两个 20 尺等价位置，因此不能同时把 20 尺和 40 尺容量独立塞满。

### 8.5 当前分配与当前使用变量联动

\[
x_{v,a}^{20}+x_{v,a}^{40}\leq M_v(\theta)z_{v,a},\quad \forall v,a
\]

其中：

\[
M_v(\theta)=R_v^{20}(\theta)+R_v^{40}(\theta)
\]

代码对应：

```python
x20[v, a] + x40[v, a] <= M_v * z[v, a]
```

含义：如果 \(z_{v,a}=0\)，则不能往该箱区分配箱子。

### 8.6 当前使用箱区必须真实分配箱子

\[
x_{v,a}^{20}+x_{v,a}^{40}\geq z_{v,a},\quad \forall v,a
\]

代码对应：

```python
x20[v, a] + x40[v, a] >= z[v, a]
```

含义：如果 \(z_{v,a}=1\)，至少分配 1 个箱子。这不是单箱区最小分配量规则，只是逻辑约束。

### 8.7 不可用箱区禁止使用约束

\[
z_{v,a}\leq 1-B_{v,a}(\theta),\quad \forall v,a
\]

代码对应：

```python
z[v, a] <= 1 - B[v, a]
```

含义：如果 \(B_{v,a}=1\)，则 \(z_{v,a}=0\)，不能使用该箱区。

### 8.8 总体箱区变量与历史、当前使用关系

\[
w_{v,a}\geq H_{v,a}(\theta^-)
\]

\[
w_{v,a}\geq z_{v,a}
\]

\[
w_{v,a}\leq H_{v,a}(\theta^-)+z_{v,a}
\]

代码对应：

```python
w[v, a] >= H[v, a]
w[v, a] >= z[v, a]
w[v, a] <= H[v, a] + z[v, a]
```

这三条约束共同表示：

\[
w_{v,a}=\max\{H_{v,a}(\theta^-),z_{v,a}\}
\]

### 8.9 非当前新增规划但仍活跃航次的总体箱区固定

对于：

\[
v\in\mathcal V^{act}(\theta),\quad v\notin\mathcal V^+(\theta)
\]

有：

\[
w_{v,a}=H_{v,a}(\theta^-)
\]

代码对应：

```python
w[v, a] == H[v, a]
```

### 8.10 第一次规划箱区数量约束

对于第一次规划航次：

\[
K_v^{min}\leq \sum_{a\in\mathcal A}w_{v,a}\leq K_v^{max}
\]

代码对应：

```python
sum(w[v, a] for a in A) >= K_min[v]
sum(w[v, a] for a in A) <= K_max[v]
```

### 8.11 第一次规划中新开箱区变量固定

第一次规划航次：

\[
n_{v,a}=0
\]

代码对应：

```python
n[v, a] == 0
```

### 8.12 后续规划新开箱区识别约束

对于后续规划航次：

\[
n_{v,a}\geq w_{v,a}-H_{v,a}(\theta^-)
\]

\[
n_{v,a}\leq w_{v,a}
\]

\[
n_{v,a}\leq 1-H_{v,a}(\theta^-)
\]

代码对应：

```python
n[v, a] >= w[v, a] - H[v, a]
n[v, a] <= w[v, a]
n[v, a] <= 1 - H[v, a]
```

### 8.13 同日开港航次避让约束

\[
w_{u,a}+w_{v,a}\leq 1+q_{u,v,a},\quad \forall (u,v)\in\mathcal P^{same}(\theta),a
\]

代码对应：

```python
w[u, a] + w[v, a] <= 1 + q[u, v, a]
```

含义：如果同日开港航次 \(u\) 和 \(v\) 都使用箱区 \(a\)，则 \(q_{u,v,a}=1\)，并在目标函数中被惩罚。

### 8.14 单箱区服务航次数限制

\[
\sum_{v\in\mathcal V^{act}(\theta)}w_{v,a}\leq 2+h_a,\quad \forall a
\]

代码对应：

```python
sum(w[v, a] for v in V_act) <= 2 + h[a]
```

含义：一个箱区最好不要服务超过 2 个活跃航次。若超过，则由 \(h_a\) 表示超额数量。

### 8.15 累计平均距离公平约束

对于当前新增规划航次：

\[
G_v(\theta^-)+\sum_{a\in\mathcal A}d_{v,a}(x_{v,a}^{20}+x_{v,a}^{40})
\leq
\eta\left[P_v^{20}(\theta^-)+P_v^{40}(\theta^-)+R_v^{20}(\theta)+R_v^{40}(\theta)\right]
\]

代码对应：

```python
G_prev[v] + sum(distance[v, a] * (x20[v, a] + x40[v, a]) for a in A) <= eta * total_planned_after
```

对于非当前新增规划但仍活跃的航次：

\[
G_v(\theta^-)
\leq
\eta\left[P_v^{20}(\theta^-)+P_v^{40}(\theta^-)\right]
\]

含义：\(\eta\) 表示所有活跃航次中的最大累计平均距离。

---

## 9. 目标函数

模型目标函数为：

\[
\min Z=
\lambda_1 Z^{dist}
+\lambda_2 Z^{fair}
+\lambda_3 Z^{frag}
+\lambda_4 Z^{same}
+\lambda_5 Z^{over}
+M^{new}Z^{new}
+M^{miss}Z^{miss}
\]

### 9.1 总距离成本

\[
Z^{dist}=\sum_{v\in\mathcal V^+(\theta)}\sum_{a\in\mathcal A}d_{v,a}(x_{v,a}^{20}+x_{v,a}^{40})
\]

含义：当前新增规划箱子尽量放到离航次泊位更近的箱区。

### 9.2 最大累计平均距离公平项

\[
Z^{fair}=\eta
\]

含义：避免某个航次被系统性分配到距离过远的箱区。

### 9.3 当前新增规划碎片化惩罚

\[
Z^{frag}=\sum_{v\in\mathcal V^+(\theta)}\sum_{a\in\mathcal A}z_{v,a}
\]

含义：当前新增箱量尽量不要分散到过多箱区。

### 9.4 同日开港共用箱区惩罚

\[
Z^{same}=\sum_{(u,v)\in\mathcal P^{same}(\theta)}\sum_{a\in\mathcal A}q_{u,v,a}
\]

含义：同日开港航次尽量不要共用箱区。

### 9.5 箱区服务航次数超额惩罚

\[
Z^{over}=\sum_{a\in\mathcal A}h_a
\]

含义：一个箱区尽量不要服务超过 2 个活跃航次。

### 9.6 后续规划新开箱区惩罚

\[
Z^{new}=\sum_{v\in\mathcal V^+(\theta)}\sum_{a\in\mathcal A}n_{v,a}
\]

含义：后续规划时，尽量不要启用第一次规划中没有使用过的新箱区。

### 9.7 未满足需求惩罚

\[
Z^{miss}=\sum_{v\in\mathcal V^+(\theta)}(s_v^{20}+s_v^{40})
\]

含义：尽量满足当前所有应规划箱量。该项权重应最大。

## 12. Codex 修改代码时的注意事项

### 12.1 不要把时间显式加到变量里

不要建立：

\[
x_{v,a,t}
\]

时间由外部滚动模块更新参数实现。

### 12.2 不要重新加入单箱区最小/最大分配量

当前版本已经删除：

\[
L_v(\theta),\quad U_v(\theta)
\]

也删除了：

\[
x_{v,a}^{20}+x_{v,a}^{40}\geq L_v(\theta)z_{v,a}
\]

\[
x_{v,a}^{20}+x_{v,a}^{40}\leq U_v(\theta)z_{v,a}
\]

只保留基本逻辑：

\[
x_{v,a}^{20}+x_{v,a}^{40}\leq M_vz_{v,a}
\]

\[
x_{v,a}^{20}+x_{v,a}^{40}\geq z_{v,a}
\]

### 12.3 第一次规划和后续规划必须区分

第一次规划：

- 施加 \(K_v^{min}\)、\(K_v^{max}\) 箱区数量约束；
- 固定 \(n_{v,a}=0\)。

后续规划：

- 不再重新控制箱区数量；
- 通过 \(n_{v,a}\) 识别新开箱区；
- 在目标函数中强惩罚 \(n_{v,a}\)。

### 12.4 不要混淆 \(w\) 和 \(z\)

- \(z_{v,a}\)：当前这一次规划是否使用箱区；
- \(w_{v,a}\)：当前规划完成后，航次总体是否使用箱区。

使用 \(w\) 的地方包括：

- 同日开港共用箱区；
- 一个箱区服务超过 2 个航次；
- 第一次规划主箱区数量控制；
- 后续规划是否新开箱区。

使用 \(x\) 和 \(z\) 的地方包括：

- 当前新增分配；
- 容量约束；
- 当前不可用箱区约束。

### 12.5 20/40 容量约束必须同时保留

必须同时保留：

\[
\sum_v x_{v,a}^{40}\leq C_a^{40}
\]

和：

\[
\sum_v x_{v,a}^{20}+2\sum_v x_{v,a}^{40}\leq C_a^{20}
\]

不能只写其中一条。

### 12.6 调试阶段建议允许未满足需求

建议调试阶段设置：

```python
allow_unmet_demand = True
```

如果模型无法完全满足需求，可以通过查看：

```python
s20
s40
```

判断哪一个航次、哪一种箱型存在容量不足。

## 13. 模型简要口径

该模型可以概括为：

> 在每个事件驱动的规划时刻，基于当前新增规划需求、箱区剩余容量、泊位距离、不可用箱区、历史已选箱区和活跃航次占用关系，求解一个混合整数线性规划模型，为出口航次的 20 尺和 40 尺箱分配箱区。第一次规划时确定主箱区集合，后续规划时优先沿用历史箱区。模型同时控制距离成本、平均距离公平性、箱区分散程度、同日开港共用箱区、单箱区服务航次数以及未满足需求。
