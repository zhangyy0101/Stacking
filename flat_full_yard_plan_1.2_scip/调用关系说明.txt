flat_full_yard_plan_2_scip 调用关系说明

一、运行入口

run_flat_full_yard_plan.py 是完整大、中、小计划流水线入口，负责串联：
1. InputAdapterGd 输入反序列化
2. 大计划输入构建和求解
3. 大计划结果可视化
4. 中计划和小计划输入构建
5. 中计划和小计划列生成求解
6. 汇总输出 pipeline_summary.json

推荐运行方式：

python run_flat_full_yard_plan.py --run-name latest_full_plan --large-quiet

也可以显式指定 adapter JSON：

python run_flat_full_yard_plan.py --adapter-json input_data.json --run-name latest_full_plan --large-quiet

如果不显式指定 --adapter-json，主脚本默认读取当前目录下的 input_data.json。

二、当前数据输入方式

input_data.json
  交付数据包，保存箱位快照、TOPS 计划、箱区功能、船舶靠泊、航次箱信息、泊位距离矩阵、历史计划等输入数据。

input_adapter_gd.py
  InputAdapterGd 的序列化/反序列化模块。
  主脚本通过 InputAdapterGd.load_from_json() 读取 input_data.json。
  JSON 中的 DataFrame split 结构会在内存中还原为 pandas DataFrame。
  计划时间直接使用 input_data.json 中的 planning_time 字段；主入口不再提供 --planning-time 手动输入。

input_adapter_standard.py
  当前 adapter 对象版数据装配模块。
  算法直接从 InputAdapterGd 对象的字段读取数据，例如：
  - bay_slots_detail
  - tops_plan
  - area_function_info
  - vessel_berth_info
  - vessel_containers
  - berth_area_dist_matrix
  - history_plan_info

重要说明：
  当前主流程不再把 input_data.json 还原并导出成一批 flat 原始输入文件。
  运行时不会生成 adapter_flat_data。
  运行时不会生成 bay_slots_detail.parquet、tops_plan_info.parquet、vessel_berth_info_new.csv、箱区功能.xlsx、适放箱区_泊位距离矩阵.xlsx、container_info_*.parquet、predict_data_*.xlsx 等临时输入文件。
  adapter_input_bridge.py 已删除。
  flat_yard_plan_data_io.py 已删除。

三、大计划模块

run_flat_full_yard_plan.py
  在 adapter 输入模式下调用 input_adapter_standard.build_large_inputs()。

input_adapter_standard.py
  build_large_inputs() 直接读取 InputAdapterGd 对象，构建 LargePlanningData。
  主要处理内容包括：
  - 自动从 vessel_containers 中发现出口、进口航次
  - 读取箱区功能、泊位、泊位距离、TOPS 计划
  - 读取箱位快照并计算可用容量
  - 读取航次箱清单和预测量
  - 使用 history_plan_info 构建上一轮计划参数

planning_large_solver.py
  solve_daily_rolling_yard_plan() 是大计划求解器。
  输入 LargePlanningData。
  输出航次、流向、箱型到箱区的大计划分配结果。

大计划主要输出：
  full_plan_outputs/<run_name>/outputs_large/latest_run/allocation.csv
  full_plan_outputs/<run_name>/outputs_large/latest_run/allocation_new.csv
  full_plan_outputs/<run_name>/outputs_large/latest_run/diagnostics.json
  full_plan_outputs/<run_name>/outputs_large/latest_run/state_rows_appended.csv

四、可视化模块

planning_large_visualize.py
  大计划求解完成后读取 allocation.csv。
  在 adapter 输入模式下，箱区功能标签直接来自 adapter.area_function_info，不再读取箱区功能.xlsx。
  生成箱区分配标注图和检查文件。

可视化主要输出：
  full_plan_outputs/<run_name>/outputs_large/yard_visualization/yard_base_original.png
  full_plan_outputs/<run_name>/outputs_large/yard_visualization/yard_allocation_annotated.png
  full_plan_outputs/<run_name>/outputs_large/yard_visualization/visualization_allocation_check.csv
  full_plan_outputs/<run_name>/outputs_large/yard_visualization/unmapped_areas.csv（仅有未匹配坐标箱区时生成）

五、中计划和小计划模块

run_flat_full_yard_plan.py
  大计划求解完成后，不再把 allocation.csv 作为中小计划的输入文件重新读取。
  adapter 输入模式下会把大计划 solution 转成内存 DataFrame，然后传给 input_adapter_standard.load_medium_small_inputs()。
  pipeline_summary.json 中 large_allocation_used_by_medium_small 会记录为 in_memory。
  中小计划求解器已切换为 medium_small_column_generation_scip.column_generation_planner.ColumnGenerationPlanner。

input_adapter_standard.py
  load_medium_small_inputs() 直接从 InputAdapterGd 对象和内存大计划结果构建 MediumSmallInputs。
  build_problem() 进一步构建中小计划 ProblemData，包括箱组、可用 bay、箱区作业冲突、泊位距离、容量等信息。

medium_small_column_generation_scip/column_generation_planner.py
  ColumnGenerationPlanner 是当前中小计划列生成求解器。
  默认使用 PySCIPOpt/SCIP 求解 LP 主问题和最终整数主问题。
  若显式传入 --cg-no-scip，才会关闭 SCIP 并走贪心兜底。
  若 SCIP 不可用或求解异常，diagnostics.json 会记录 used_greedy_fallback 和 scip_failure。

中小计划主要输出：
  full_plan_outputs/<run_name>/medium_small_plan/medium_plan.csv
  full_plan_outputs/<run_name>/medium_small_plan/small_plan.csv
  full_plan_outputs/<run_name>/medium_small_plan/small_plan_six_bay_blocks.csv
  full_plan_outputs/<run_name>/medium_small_plan/medium_demand_by_port.csv
  full_plan_outputs/<run_name>/medium_small_plan/generated_columns.csv
  full_plan_outputs/<run_name>/medium_small_plan/big_plan_used.csv
  full_plan_outputs/<run_name>/medium_small_plan/diagnostics.json

说明：
  当前列生成版本不再输出 energy_convergence.csv。
  generated_columns.csv 记录列生成候选列。
  diagnostics.json 记录列生成口径、SCIP 是否可用、是否走贪心兜底、最终主问题状态、MIP gap、未放置惩罚变量等诊断信息。

六、当前整体数据流

input_data.json
  -> input_adapter_gd.py 反序列化为 InputAdapterGd 对象
  -> input_adapter_standard.py 直接从对象字段构建大计划输入
  -> planning_large_solver.py 求解大计划
  -> planning_large_visualize.py 生成可视化
  -> input_adapter_standard.py 使用内存大计划结果构建中小计划输入
  -> medium_small_column_generation_scip/column_generation_planner.py 用列生成求解中计划和小计划
  -> run_flat_full_yard_plan.py 汇总输出

七、列生成相关入口参数

run_flat_full_yard_plan.py 中当前暴露的中小计划列生成参数包括：
  --cg-max-iterations
  --cg-columns-per-iteration
  --cg-initial-columns-per-group
  --cg-max-candidate-bays-per-group
  --cg-mip-time-limit
  --cg-mip-gap
  --cg-demand-mode
  --cg-no-scip
  --cg-quiet
  --cg-fine-group-area-penalty
  --cg-fine-group-block-penalty
  --cg-fine-group-bay-penalty
  --cg-coarse-area-block-penalty
  --cg-coarse-area-bay-penalty
  --cg-medium-concentrated-group-threshold
  --cg-medium-small-group-area-split-penalty
  --cg-medium-small-group-fragment-penalty
  --cg-medium-large-group-min-area-boxes
  --cg-medium-large-group-small-area-penalty

默认 --cg-demand-mode 为 original，用于对齐原中计划和资料箱小计划口径。
默认使用 SCIP；只有传入 --cg-no-scip 时才禁用 SCIP。
